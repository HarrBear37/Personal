Accessiblility Issues With JavaScript

Many websites are made with what is believed to be the common reader in mind, the mouse user. Although, the majority of readers, this being 89.9%, according to WebAIM, have disabilities that inhibit their way of navigating the Web. These readers use keyboards or screen readers. Unfortunately, these readers struggle to navigate websites because they are made without them in mind.

Plenty of frustration comes from focus management. This is caused when web designers remove focus indicators from the browser.

1

Example:

:focus {
outline: none;
}

Just keep it on! It's a simple fix. It can further assist by changing the color or thickness of the bubble.

input:focus {
  background-color: yellow;
  width: 250px;
}
|

For further details about :focus click here: Focus Indicators

Focus Traps occurs when readers are unable to focus outside of a modal. But without proper testing, the user can leave the modal. To prevent this, the designer must test the site by tabbing through it. A proper modal will return focus to the first element of the site.

Something to keep in mind is what will be first focused on first when loading the page or a dynamic refresh. This could be the title of an article, modal, or notification. As always, issues may arise. The focus must change to the most relevant content on the page.

While tabbing through a page, the page should have a flow. To prevent confusion, the designer must make the Focus Order go through the most important elements. Keep it predictable!

It is important to keep the reader in mind when creating a site. These simple solutions bring accessibility and appreciation to keyboard users and screen readers. The Web has so much valuable information, why should we deny it to those with disabilities?

WebAIM is a great website to learn about web accessibility. It not only teaches focus indicators but also any other ways to keep web accessibility in mind.
